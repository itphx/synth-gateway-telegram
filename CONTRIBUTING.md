# Contributing to synth-gateway-telegram

Thanks for your interest in improving the Synth Telegram gateway! This repository
implements the **Telegram gateway** — an external bridge service (**Gateway**) for
the [Synth](https://gitverse.ru/itphx/synth) agent platform.

A Russian version of this document is available: [CONTRIBUTING.ru.md](./CONTRIBUTING.ru.md).

## Development model and pull requests

- **Canonical development happens in GitVerse** —
  <https://gitverse.ru/itphx/synth-gateway-telegram> (branch `master`).
- **GitHub is a public mirror** — <https://github.com/itphx/synth-gateway-telegram>.
  Issues and pull requests are welcome there, but the maintainer does **not** merge
  them on GitHub: accepted changes are **cherry-picked into GitVerse**. Please keep
  the branch rebased on `master` so it applies cleanly.
- One logical change per pull request. Describe what and why.

## Requirements

- **Node.js ≥ 22** (see `engines` in [`package.json`](./package.json)).
- **pnpm** (the repository is a single pnpm package with a committed lockfile).
- Git.

## Getting started

```bash
git clone https://gitverse.ru/itphx/synth-gateway-telegram.git
cd synth-gateway-telegram
pnpm install
```

## Checks

Run all of these from the repository root before opening a pull request. The
command names below are the exact scripts from [`package.json`](./package.json):

| Command | Purpose |
|---|---|
| `pnpm build` | Compile TypeScript to `dist/` (`tsc -p tsconfig.build.json`) |
| `pnpm typecheck` | Type-check without emitting (`tsc --noEmit`) |
| `pnpm lint` | Run ESLint on `src/` |
| `pnpm test` | Run Vitest (`vitest run`) |
| `pnpm start` | Start the gateway from `dist/` (`node dist/gateway/index.js`) |
| `pnpm clean` | Remove `dist/` |

Local pre-flight check:

```bash
pnpm build && pnpm typecheck && pnpm lint && pnpm test
```

## Branch naming

| Prefix | Use for |
|---|---|
| `feat/*` | New functionality |
| `fix/*` | Bug fixes |
| `docs/*` | Documentation only |
| `chore/*` | Tooling, CI, dependencies, housekeeping |

## Commit messages — Conventional Commits

Use [Conventional Commits](https://www.conventionalcommits.org/) with a **Russian**
description:

```text
<type>(<scope>): <краткое описание в повелительном наклонении>
```

Allowed types: `feat`, `fix`, `docs`, `refactor`, `test`, `ci`, `chore`.
`scope` is optional (for example `fix(gateway): …` or `fix(docker): …`).

Examples:

```text
fix(gateway): устранить повтор доставки при перезапуске поллера
feat(mcp): добавить тул tg_status
docs(deployment): описать деплой через Helm
```

## Sign-off (DCO)

Every commit must be signed off to certify the
[Developer Certificate of Origin](https://developercertificate.org/):

```bash
git commit -s -m "fix(gateway): ..."
```

The `Signed-off-by:` line is required; pull requests without it cannot be accepted.

## Versioning

The version is a single source of truth in three places: `package.json`,
`synth.pack` and the Helm chart's `Chart.yaml`. Do not bump them by hand — use

```bash
./scripts/version-bump.sh <X.Y.Z>
```

then commit and tag `vX.Y.Z`. Release notes are generated by CI and published on
the Releases page (see [CHANGELOG.md](./CHANGELOG.md)).

## The `synth.pack` manifest

`synth.pack` (JSON in the repository root, no file extension) is the single
extension manifest: it declares `kind: "gateway"`, `host`, `contracts` and
`provides` (MCP server and skills).

- If you change the gateway **composition** — add/remove an MCP server or a skill,
  change `kind`/`host`/`contracts` — update `synth.pack` **and** its `version`
  (via `scripts/version-bump.sh`).
- Keep the manifest in sync with what the Helm chart actually installs.

## Documentation

- Documentation lives in `docs/*.md`
  ([gateway.md](./docs/gateway.md), [configuration.md](./docs/configuration.md),
  [deployment.md](./docs/deployment.md)). Update the relevant page whenever
  behaviour, configuration or deployment changes.
- Keep [README.md](./README.md) consistent with the code.
- Documentation is written in **Russian**.

## Secrets

- **Never commit secrets.** Bot tokens, Synth service keys, OIDC client secrets
  and `tenants.json` must stay out of git: `secrets/`, `certs/` and `.env` are
  git-ignored.
- Example manifests under `examples/` must contain **placeholders only**
  (for example `REPLACE_ME`) — never real tokens, keys or certificates.
- Use a Secret manager or `SealedSecret` in production, not committed files.
